### Component 1: Canonical SQL source tree

```text
zcordis-pgembed/
└── sql/
    ├── 0000_kernel.sql
    └── README.md
```

`sql/README.md` is documentation only (not executed).

**Filename contract.** Apply discovers only **direct children** of the SQL root with suffix `.sql`. Valid names:

```text
NNNN_slug.sql
```

- `NNNN` is exactly four decimal digits;
- `slug` starts with a lowercase letter or digit; remainder `[a-z0-9_]` only;
- numeric prefix is unique;
- `0000_kernel.sql` must exist.

Valid examples: `0000_kernel.sql`, `0001_p01_claim.sql`, `0002_p02_log.sql`.

Invalid: `kernel.sql`, `001_p01.sql`, `0001-p01.sql`, `0001_p01.SQL`, nested `sql/migrations/0001.sql`. Duplicate prefixes (`0001_first.sql` and `0001_second.sql`) fail even if full names differ.

Gaps are allowed (`0000` then `0010`) so a plan item can reserve a range.

P00 must not contain a nested `.sql` directory. A future migration subsystem is a separate design, not a second silent apply path.

**`discover_sql_files(sql_root)`:** resolve path; must be a directory; reject invalid names, nested `.sql`, duplicate prefixes; require `0000_kernel.sql`; return files ordered by numeric prefix. Fail **before** database mutation. Default SQL root is resolved from the script’s repository location, not cwd.

**Rules for later Pxx files.** Add higher-numbered files only. **Do not edit historical numbered files as the release mechanism**; a replay of an edited old file may succeed but the intended path is append. Do not edit the apply command’s file list, add a manifest, depend on pg-agent files, place kernel objects in `public`, use `scratch/` as a source dependency, or add a second queue/extension.

Every numbered SQL file must be: safe to replay after preceding files; valid inside the apply transaction; free of `\connect`, `\include`, `\ir`, `\!`, transaction-control, and database-creation commands; schema-qualified (independent of caller `search_path`); free of dropping the target database or `pg_cordis` schema.

### Component 2: Empty kernel bootstrap

`0000_kernel.sql` creates schema `cordis` idempotently (`CREATE SCHEMA IF NOT EXISTS`). PostgreSQL rejects `pg_cordis` (`pg_` prefix). It does not change ownership or ACLs on an existing schema. It must not contain `GRANT`, `ALTER DEFAULT PRIVILEGES`, role creation, or `GRANT USAGE ON SCHEMA`. Permission management is deferred to later kernel/grant work (P07+). It must not create `public` objects, `absurd` schema, roles, extensions, tables, enums, queues, worker functions, or log/run objects. The schema is a **namespace**, not a queue.

The executing role is pgembed’s `postgres` superuser (empty password). The apply command does not create a dedicated role. If another role already owns the schema or function, report the PostgreSQL permission error and stop (do not steal ownership).

Version function:

```text
pg_cordis.get_schema_version() → text
```

P00-only tree returns exactly `p00`. Pure SQL, no table reads, immutable, security-invoker. Installation marker, not agent SoT.

Later Pxx: the latest contract file may update the function’s return value to a cumulative marker; the apply command does **not** use the function to select files; filename order remains authoritative.

If an existing `cordis` schema or function is owned by another role, report the PostgreSQL permission error and stop. Do not drop or steal ownership.

### Component 3: Apply CLI

```text
python tools/apply_pg_cordis.py
  --pgdata PATH          # required; passed to pgembed.get_server
  --database NAME        # required; target DB
  [--sql-root PATH]      # default: repo sql/ from script location
  [--reset]              # drop+recreate target (destructive)
```

Synchronous script in this repo’s uv project. Not a published package, not a pgembed patch. May use stdlib, `pgembed.get_server`, `pgembed.POSTGRES_BIN_PATH`, subprocess `psql`. Must not import `pg-agent.server`, pg-agent SQL, `psycopg2`, or private pgembed internals. No `--url` / remote-Postgres mode in P00.

`pyproject.toml` mirrors pg-agent’s pgembed pin (`requires-python >=3.12`, `pgembed>=0.3.0rc1`, `[tool.uv] prerelease = "allow"` and **`package = false`**, `[tool.uv.sources] pgembed = { path = "../pgembed", editable = true }`). **`[dependency-groups] dev = ["pytest"]`** (not an optional extra — `uv run pytest` must work without extra flags). No `[build-system]`. Do **not** add `psycopg2`. Project name: `pg-cordis`. Default documented `--pgdata` for P00-only tests: `$CORDIS_ROOT/.pgdata`. README also documents `uv run --project "$CORDIS_ROOT" python tools/apply_pg_cordis.py …` from any cwd.

Exit: `0` success; `1` runtime/SQL/verify failure; `2` CLI or source-tree validation **before** mutation.

Print: resolved PGDATA, database, source root, in-place vs reset, ordered files, success/failure.

**Database-name validation** before interpolating SQL: **`[a-z_][a-z0-9_]*` only** (lowercase). Unquoted `CREATE DATABASE` folds case, while `get_uri(name)` copies the name into the URI (`pgembed/src/pgembed/utils.py:100-106`); uppercase names would create `cordis_p00` then fail to connect as `Cordis_P00`. Reject empty, whitespace, punctuation, uppercase, `template0`/`template1`. `--reset --database postgres` rejected. `postgres` allowed only for non-destructive in-place install.

**Sequence:** (1) validate SQL tree; (2) `pgembed.get_server(Path(--pgdata))`; (3) admin URI `server.get_uri("postgres")`; (4) query `pg_database`; (5) create target if missing; (6) if `--reset` and exists: `DROP DATABASE … WITH (FORCE)` then recreate; (7) `server.get_uri(database)`; (8) apply tree; (9) verify bootstrap.

Create/drop via bundled `psql`, not a pgembed API. Race: two in-place creates of a missing DB — if “already exists”, recheck `pg_database`; continue only if the target now exists; **otherwise exit 1 with the original create error**. `--reset` is not concurrency-safe.

**SQL execution:** URI from `get_uri(database)`; `POSTGRES_BIN_PATH/psql`; `--no-psqlrc`; `ON_ERROR_STOP=1`; `--single-transaction`; SQL on stdin; no `shell=True`. In-memory stream: (1) **on the target-database connection**, `SELECT pg_advisory_xact_lock(hashtext('pg_cordis.apply'));` as the first statement (lock is per-database; second in-place apply waits with **no timeout** — known P00 behavior, keep tests serial); (2) per-file source-boundary comments; (3) file contents in order. Newline-separate even if a file lacks a trailing newline. Tree-wide transaction: failure in a later file rolls back `0000` in that invocation. Files must be transaction-safe.

**Post-apply verification** after commit: schema `cordis` exists; `cordis.get_schema_version()` exists, no args, returns `text`. Generic apply must **not** require the value `p00` (later Px may change the marker). P00 tests assert `p00` when the tree contains only `0000_kernel.sql`. Do not verify P01+ objects.

### Component 4: Reinstall semantics

**Default (no `--reset`):** create DB if absent; leave unrelated objects; replay every numbered file; do not drop schemas/tables/data; commit only if the whole tree succeeds. Second P00 invocation must succeed with the same effective objects. Newly added numbered files are picked up with no Python change.

**`--reset`:** admin `postgres` DB → force-drop target if exists → create → apply. For disposable tests only; print that it is destructive. If SQL fails after reset, expected state is: target DB exists, **none** of the tree’s objects committed (tree is one transaction). Database creation itself is outside that transaction.

**No uninstall/downgrade.** Deleting a source file does not drop its objects. Older checkout on a newer DB is unsupported. Test older source with `--reset` on a disposable DB. Do not automate `DROP SCHEMA pg_cordis CASCADE` (future runtime state will live there).

Later files: `CREATE OR REPLACE` / `IF NOT EXISTS` / guarded type creation; no unconditional teardown. If a change cannot be replayed safely, it needs a separate migration design — not a silent weakening of P00 apply.

### Component 6: State and data flow

Fresh in-place: CLI → validate tree → `get_server` → create DB if missing → advisory lock → one transaction → schema + version function → verify → exit 0.

Persistent P00 state: schema `cordis` and `cordis.get_schema_version()` only. No agent/queue/log/workspace state.

Reapply: skip create; replay; `IF NOT EXISTS` + `CREATE OR REPLACE` make the second call succeed.

Adding P01: add `sql/0001_p01_claim.sql`; no loader change. P00 tests copy `sql/` to a temp dir and add `0001_p01_probe.sql` (not in the product tree).

Failures: validation → no server mutation; prep fail → no tree transaction; SQL fail → full rollback; interrupt → connection close rolls back and releases lock; `--reset` interrupt may leave a dropped/empty DB; verify fail after commit → exit 1, leave DB for diagnosis.

### Component 7: Concurrency and lifecycle

In-place applies to the same DB serialize on a transaction advisory lock, released on commit/rollback/disconnect. `--reset` documents that no other process may use the target (`DROP DATABASE … WITH (FORCE)` kills sessions).

`get_server(pgdata)` reuses a running instance. Do not modify `PostgresServer`, instance lock, cleanup, or delete PGDATA. Script is synchronous; no threads/async workers.

### Component 8: Error handling and edge cases

| Condition | Required behavior |
|---|---|
| `--pgdata` or `--database` omitted | Exit 2 |
| Invalid database identifier (including uppercase) | Exit 2 before mutation |
| `sql-root` absent / not a directory | Exit 2 |
| No SQL files / missing `0000_kernel.sql` | Exit 2 |
| Invalid name / duplicate prefix / nested `.sql` | Exit 2 |
| `pgembed` unavailable or bundle not attested | Exit 1 |
| Cannot connect to `postgres` / cannot create target | Exit 1 |
| Schema/function owned by another role | Exit 1; do not drop or steal |
| SQL syntax or dependency failure | Exit 1; tree rolls back |
| Incompatible `CREATE OR REPLACE` signature | Exit 1; report PostgreSQL error |
| Unrelated public objects in target | In-place preserves them |
| Target missing | Create, then apply |
| Reset of `postgres` / `template0` / `template1` | Exit 2 |
| Reset with active clients | Force-drop per explicit reset contract |
| Interrupted apply | Rollback active transaction |
| Verify fails after commit | Exit 1; keep DB |
| Empty SQL file after `0000` | Still loaded |
| P01 file references pg-agent `public` objects | Source-contract violation; reject in review/tests |

## Risks and migration

- No row migration (no runtime tables). Version function is not an upgrade ledger.
- `--reset` force-drops the target; document as test-only. Default command omits it.
- In-place replay is not downgrade support. Use `--reset` on a disposable DB to test an older checkout.
- Later numbered files must stay transaction-safe and replayable; non-replayable DDL needs a new design.
- Foreign ownership of `pg_cordis` blocks in-place apply; report, do not steal.
- Sibling-path `pgembed` (`../pgembed`) must exist for `uv sync`; if the checkout layout differs, `[tool.uv.sources]` must be edited. Not a published PyPI package in P00.
- Composition proves shared-server coexistence, not same-database runtime integration (evaluate after P01 schema-qualified objects exist).
